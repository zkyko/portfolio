systems

Problems I found, and what I built.

Each one started as a real, annoying bottleneck in how work actually got done.

/work/01
FH Connect Hub
live · production

The internal EDI support hub — mail, Jira, Confluence, and customer data in one app, with an AI assistant.

PROBLEMEDI support was scattered across an Outlook mailbox, Jira, Confluence, and Mentis — no single view, every partner email triaged by hand.
BUILTOne app that unifies them. Every email is AI-summarized, tagged, and tied to a customer; one click turns it into a Jira ticket; resolved tickets become Confluence fix notes. Node/Express · React · Azure SQL · Azure AI Foundry · Mentis GraphQL · Logic Apps
/work/02
fh-d365-mcp
mcp server

An MCP server that lets AI agents read D365 Finance & Operations — without a browser or hand-written OData.

PROBLEMQA and AI assistants had to open D365 in a browser, or hand-write OData calls, just to check a customer record or entity schema.
BUILTA read-only MCP server exposing entities, schemas, enums, and labels — with a hard policy gate rejecting anything but read-only Four Hands hosts before a token is ever attached. Python · MCP · D365 OData · Key Vault
/work/03
Account Insights
proof of concept

A quick-glance account health view inside Salesforce, scored from real Mentis purchasing data.

PROBLEMReps had no fast way to see an account's purchasing, product, and inventory health before a visit.
BUILTA Salesforce LWC + Apex app that snapshots Mentis data into a weighted health score, with a printable PDF brief — reconciled exact against production data. LWC · Apex · Mentis GraphQL · Salesforce
/work/04
QA Hub
dashboard

Real-time visibility into CI pipelines as living agents, with run history and pending approvals.

PROBLEMPipelines were invisible — you couldn't tell "idle because nothing qualified" from "actually down."
BUILTA dashboard that maps each pipeline job to a live agent with status, run history, and a real pending-approvals panel. Node · Azure DevOps · Logic Apps
